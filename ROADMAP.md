## Требования и границы первой версии

Обязательные требования задания:

- Сервер отдаёт поездки и финансовую сводку за выбранный день.
- Клиент показывает сводку и список поездок и позволяет переключать дни.
- Через API можно добавить поездку с проверкой данных.
- Повторная отправка той же поездки не создаёт дубль.
- Расчёты сводки и защита от дублей покрыты тестами.
- Для сдачи нужен публичный репозиторий с README о запуске и выполненной работе,
  а также честное описание применения ИИ. Демо и скриншоты необязательны.

Дополнительно включены простая форма добавления во Flutter, аккуратный интерфейс,
CI и скриншоты. Целевые платформы — Android и iOS.

Первая версия рассчитана на одного водителя. Авторизация, несколько водителей,
офлайн-синхронизация и публичный деплой в неё не входят.
Публикация репозитория и отправка анкеты выполняются отдельно по запросу пользователя.

## Правила данных и расчётов

- Валюта — KZT. `amount` и `commission` — целые тенге. Использовать целочисленные
  поля в API, БД и Dart; не применять `float`/`double` для денег.
- `commission` — денежная сумма, а не процент. Она должна быть неотрицательной.
- Выручка — сумма `amount`; комиссия — сумма `commission`;
  «на руки» — выручка минус комиссия.
- Наличные и карта — суммы выручки по соответствующему способу оплаты.
  Их сумма равна общей выручке.
- Число поездок — количество записей за выбранный день.
- День определяется началом поездки в часовом поясе `Asia/Almaty`, независимо
  от часового пояса телефона или процесса сервера.
- Поездка через полночь целиком относится к дню начала.
- Интервал дня включает местную полночь и исключает полночь следующего дня.
- В API `start` и `end` передаются в ISO 8601 с часовым смещением.
  При хранении и сравнении нормализовать время в UTC.
- Пустой день возвращает пустой список и нулевые показатели.

## Минимальный контракт API

### Чтение дня

`GET /api/v1/days/{date}`, где `date` имеет формат `YYYY-MM-DD`.

Ответ содержит выбранную дату, список поездок и сводку: число поездок, выручку,
комиссию, «на руки», выручку наличными и картой. Денежные значения — целые числа.
Поездки отсортированы по времени начала, новые сверху.

### Добавление поездки

`POST /api/v1/trips` принимает поля исходного формата:

| Поле | Значение |
|---|---|
| `id` | Строковый идентификатор поездки |
| `start` | Начало, ISO 8601 с часовым смещением |
| `end` | Окончание, ISO 8601 с часовым смещением |
| `amount` | Положительное целое число тенге |
| `payment` | `cash` или `card` |
| `commission` | Неотрицательное целое число тенге |

Окончание должно быть строго позже начала. Неверные данные возвращают `422`.

| Сценарий | Результат |
|---|---|
| Новый ID и корректные данные | `201`, созданная поездка |
| Тот же ID и те же нормализованные данные | `200`, существующая поездка |
| Тот же ID и другие данные | `409`, конфликт |

Уникальность ID обеспечивает БД. Защита должна работать при конкурентных запросах
и после перезапуска сервера, без реестра ID только в памяти.
Равные моменты времени с разными часовыми смещениями считаются равными.
Разные ID обозначают разные поездки, даже если остальные поля совпали.

Flutter генерирует UUID один раз на отправляемую поездку.
При повторе после сетевой ошибки сохраняются и ID, и данные запроса.
Импорт JSON использует те же правила идентичности и конфликта.

- Начало ровно в полночь, конец интервала дня, поездка через полночь,
  разные часовые смещения и независимость от системного часового пояса.
- Нулевая/отрицательная/дробная сумма, отрицательная/дробная комиссия,
  неверный способ оплаты, неверная дата и время без смещения,
  окончание раньше начала или одновременно с ним.
- Последовательные и конкурентные повторы, конфликт данных одного ID,
  повторный импорт и сохранность после перезапуска.
- Во Flutter: смена дней, запоздалые ответы, загрузка, ошибка и повтор,
  пустой день, форма, добавление и обновление сводки.
